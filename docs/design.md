# 마감선 디자인 기준

## 1. 이 도구가 하는 일

여러 거래처의 업무를 빠짐없이 기록하고, 마감시간이 가까운 순서대로 처리하도록 돕는다.

화면의 모든 디자인 결정은 사용자가 다음 세 가지를 빠르게 알아내도록 도와야 한다.

1. 지금 처리해야 할 업무가 무엇인가?
2. 마감까지 얼마나 남았는가?
3. 어떤 업무를 처리하거나 취소했는가?

## 2. 핵심 원칙

- **우선순위가 먼저다:** 거래처별로 묶기보다 모든 미처리 업무를 마감 우선순위로 보여준다.
- **색과 글자를 함께 쓴다:** 상태색만 보여주지 않고 상태 문구를 반드시 표시한다.
- **원색은 작게 쓴다:** 지정 색상은 상태선, 테두리, 배지 및 활성 필터처럼 작은 면적에 사용한다.
- **넓은 면은 연하게 쓴다:** 카드 배경에는 원색의 밝은 파생색을 사용해 본문 가독성을 지킨다.
- **완료보다 미처리가 먼저다:** 사용자가 다음 행동을 결정하는 데 필요한 내용을 화면 위쪽에 둔다.
- **장식보다 행동이다:** 입력, 마감 확인, 처리 기능과 무관한 요소는 추가하지 않는다.

## 3. 색상 체계

### 지정 원색

| 의미 | 이름 | 원색 | 사용 위치 |
|---|---|---:|---|
| 미처리 공통 | 노란색 | `#FEEC41` | 미처리 카드 테두리, 미처리 활성 필터 |
| 진행 중 | 하늘색 | `#44ACFF` | 상태선과 상태 강조 |
| 마감 임박 | 보라색 | `#B331F1` | 상태선, 상태 강조, 임박 애니메이션 |
| 기한 지남 | 빨간색 | `#E03F4F` | 상태선과 상태 강조 |
| 처리 완료 | 녹색 | `#129990` | 완료 카드 테두리, 상태선, 처리된 업무 건수 |

### 배경용 파생색

| 의미 | 배경색 | 사용 이유 |
|---|---:|---|
| 미처리 카드 | `#FFFBE0` | 노란색의 의미는 유지하면서 긴 업무 문구를 읽기 쉽게 한다. |
| 진행 중 배지 | `#E8F5FF` | 하늘색 원색보다 글자 대비가 안정적이다. |
| 마감 임박 배지 | `#F6E8FD` | 보라색 상태를 부드럽게 확장한다. |
| 기한 지남 배지 | `#FDEBED` | 빨간색 경고를 유지하면서 과도한 자극을 줄인다. |
| 처리 완료 카드 | `#E5F6F4` | 완료 상태를 구분하되 미처리 업무보다 시선을 덜 끈다. |

원색을 카드 전체 배경으로 사용하지 않는다. 특히 `#FEEC41`과 `#44ACFF` 위에 작은 흰색 글자를 올리지 않는다.

## 4. 상태 규칙

### 진행 중

- 조건: 마감까지 30분보다 많이 남은 미처리 업무
- 문구: `진행 중`
- 색상: 하늘색 `#44ACFF`
- 위치: 기한 지남과 마감 임박 업무 다음

### 마감 임박

- 조건: 마감까지 30분 이하로 남은 미처리 업무
- 문구: `마감 임박`
- 색상: 보라색 `#B331F1`
- 효과: 상태에 처음 진입할 때 최대 3회 천천히 강조한 뒤 정지

### 기한 지남

- 조건: 마감시간이 지난 미처리 업무
- 문구: `기한 지남`
- 색상: 빨간색 `#E03F4F`
- 위치: 미처리 목록의 가장 위

### 처리 완료

- 조건: 사용자가 해당 업무의 `처리` 버튼을 누름
- 문구: `처리 완료`
- 색상: 녹색 `#129990`
- 위치: 진행 목록과 분리된 `처리된 업무` 영역
- 표현: 연한 녹색 배경과 취소선으로 완료를 보여주되 카드 전체 투명도는 낮추지 않는다.

## 5. 화면 정보 순서

1. **헤더:** 제품명과 오늘 날짜
2. **업무 현황:** 중앙의 남은 업무 수와 주변의 상태별 업무 건수
3. **새 업무 등록:** 거래처명, 처리할 업무, 처리 마감시간, `업무 추가`
4. **업무 검색:** 거래처명 또는 업무 내용 검색
5. **확인 필터:** `미처리`, `취소됨`, `진행·취소`
6. **진행 업무 목록:** 현재 검색과 필터에 맞는 미처리 또는 취소 업무 카드
7. **처리된 업무:** 완료 내용, 처리 시각과 후속 업무 추가 버튼
8. **푸터:** 제품 목적을 설명하는 짧은 문구

## 6. 정렬 기준

미처리 업무는 다음 순서로 표시한다.

1. 기한 지남
2. 마감 임박
3. 진행 중

각 상태 안에서는 마감시간이 빠른 업무가 먼저다. 상태와 마감시간이 모두 같고 거래처도 같을 때 접수 번호가 빠른 업무를 먼저 표시한다. 접수 번호는 문의가 들어온 이력을 나타내며 실제 처리 우선순위보다 앞설 수 없다. 처리 완료 업무는 별도 영역에서 최근 완료한 업무부터 보여준다.

## 7. 업무 카드 구성

카드 한 장은 실제로 처리할 업무 한 건을 뜻한다.

- 왼쪽 상태선
- 거래처명
- 거래처별 접수 번호
- 상태 배지
- 업무 내용
- 마감 날짜와 시간
- 남은 시간 또는 지난 시간
- 미처리 상태의 `처리` 버튼
- 완료 상태의 완료 시각
- 미처리 상태의 `수정`과 `업무 취소` 버튼
- 모든 상태의 `삭제` 버튼
- 취소 상태의 취소 시각

같은 거래처의 업무도 합치지 않고 각각 별도의 카드로 표시한다.

## 8. 여백과 크기

- 데스크톱 콘텐츠 최대 너비: `1180px`
- 화면 좌우 기본 여백: `24px`
- 큰 영역 사이 간격: `64–72px`
- 업무 카드 사이 간격: `10px`
- 업무 카드 내부 여백: 세로 `24px`, 가로 `28px`
- 입력 요소와 주요 버튼 높이: `50px`
- 모바일 좌우 여백: `14px`
- 모바일에서는 입력 항목과 버튼을 한 열로 배치한다.

수치보다 중요한 기준은 관련 정보는 가까이, 서로 다른 행동 영역은 충분히 떨어뜨리는 것이다.

## 9. 문구 기준

- 제목과 상태는 짧게 쓴다.
- 버튼은 누른 뒤 일어나는 일을 표현한다: `업무 추가`, `처리`.
- 입력 라벨은 일관되게 쓴다: `거래처명`, `처리할 업무`, `처리 마감시간`.
- 오류는 사용자가 바로 고칠 수 있게 쓴다: `거래처명을 입력해 주세요.`
- 현황은 숫자를 포함해 구체적으로 쓴다: `확인이 필요한 업무 2건`.
- 추상적인 홍보 문구, 전문 용어, 불필요한 영문 표현은 핵심 기능 영역에서 사용하지 않는다.

## 10. 상호작용 기준

- 입력값이 비어 있으면 등록하지 않고 해당 입력란 바로 아래에 오류를 표시한다.
- 업무 추가 후 입력값을 초기화하고 거래처명 입력란으로 초점을 돌린다.
- 새 업무의 접수 번호는 같은 거래처에서 사용한 가장 큰 번호의 다음 번호를 기본 제안한다.
- 접수 번호를 수정할 수 있지만 목록 정렬에서는 상태와 마감시간을 항상 먼저 적용한다.
- `수정`을 누르면 기존 내용을 상단 입력란에 불러오고 `수정 완료`와 `수정 취소`를 제공한다.
- `처리`를 누르면 해당 업무만 완료 상태로 바뀐다.
- 처리 완료 업무는 진행 목록에서 빠지고 별도의 처리된 업무 영역에 기록된다.
- 처리 기록의 `후속 업무 추가`를 누르면 거래처명과 다음 접수 번호만 새 입력란에 불러온다.
- `업무 취소`를 누르면 삭제하지 않고 `취소됨` 상태로 남긴다.
- `삭제`를 누르면 거래처명과 업무명을 포함한 확인창을 표시하고, 사용자가 확인한 경우에만 영구 삭제한다.
- 필터의 선택 상태는 색상과 눌림 상태로 함께 표시한다.
- 새로고침 후에도 업무, 완료 상태, 현재 계산된 마감 상태가 유지되어야 한다.
- 마감 상태는 앱이 열려 있는 동안 주기적으로 갱신한다.
- 곡선형 검색창에 입력하면 현재 상태 필터 안에서 거래처명과 업무 내용을 즉시 검색한다.
- 검색창은 밝은 테마, 평평한 형태, 버튼과 아이콘이 없는 구성으로 사용하며 휴대폰 폭에서는 컨테이너 너비를 넘지 않는다.
- 업무 카드는 목록을 스크롤할 때 위쪽에 순서대로 겹치며 약한 축소 효과로 깊이를 표현한다.
- 카드 스택 효과는 정렬이나 버튼 조작을 방해하지 않아야 하며, 모션 감소 설정에서는 일반 목록으로 표시한다.
- 업무 현황의 상태별 건수는 중앙의 남은 업무 수 주변을 타원 형태로 회전하며 실제 데이터가 바뀔 때 갱신한다.
- 궤도 항목은 기존 상태색을 사용하고, 모션 감소 설정에서는 회전하지 않는다.

## 11. 접근성 기준

- 모든 입력란에 화면에 보이는 라벨을 둔다.
- 상태를 색상만으로 전달하지 않는다.
- 작은 상태 글자는 원색보다 대비가 높은 짙은 파생색을 사용한다.
- 완료 카드 전체에 `opacity`를 적용하지 않는다. 글자와 버튼의 대비까지 낮아지기 때문이다.
- 키보드 초점이 보이도록 입력란과 버튼에 명확한 포커스 표시를 둔다.
- 애니메이션은 짧고 제한된 횟수로 끝나야 한다.
- 마우스 사용 환경에서 버튼과 업무 카드에 올리면 `0.2초` 동안 약 `2px` 떠오르며, 모션 감소 설정에서는 이 효과를 적용하지 않는다.

## 12. 하지 않을 것

- 거래처별 대시보드나 프로젝트 구조를 추가하지 않는다.
- 사진, 성과 차트, 장식용 그래프를 넣지 않는다.
- 완료 업무를 진행 업무 영역에 섞어 표시하지 않는다.
- 색상만 보고 상태를 추측하게 만들지 않는다.
- 업무를 취소할 때 기록을 즉시 삭제하지 않는다.
- 많은 정보를 한 화면에 억지로 압축하지 않는다.

- [ ] 접수 번호와 마감 우선순위가 충돌할 때 상태와 마감시간이 먼저 적용되는가?

- [ ] 후속 업무 추가 시 기존 완료 기록을 유지하고 새 업무 입력만 시작하는가?

- [ ] 검색창이 휴대폰 폭에서 화면 밖으로 나가지 않는가?

- [ ] 모바일과 모션 감소 환경에서 카드의 글자와 버튼을 정상적으로 사용할 수 있는가?

- [ ] 궤도 현황이 모바일에서 잘리지 않고 모션 감소 설정에서 정지하는가?

### 이메일 기기 연결

- 기존 업무 화면은 바로 보여주고 헤더에 작은 연결 상태 문구와 `기기 연결` 버튼을 둔다.
- 연결 창은 기존 종이색 배경, 초록색 안내 문구와 노란색 선택 상태를 사용한다.
- `현재 업무 연결`과 `업무 불러오기`를 같은 창에서 전환하며 현재 선택을 색상과 `aria-pressed`로 함께 표시한다.
- 비밀번호 입력 없이 이메일 입력란과 인증 메일 보내기 버튼만 표시한다.
- 오류와 성공 안내는 색상뿐 아니라 문구로 전달하고 키보드 초점 표시를 유지한다.
- 휴대폰 360px 폭에서는 연결 창의 입력란과 버튼을 한 열로 배치해 화면 밖으로 나가지 않게 한다.
