# YS-DW 처리업무 확인 리스트 PRD

## 1. 문서 개요

- **제품명:** YS-DW 처리업무 확인 리스트
- **문서 상태:** MVP 초안
- **제작 가능 시간:** 2시간
- **목적:** 여러 거래처에서 동시에 발생하는 업무를 빠짐없이 기록하고, 마감시간이 가까운 업무부터 처리할 수 있게 한다.

## 2. 대상과 문제
### 대상

여러 거래처의 업무를 동시에 진행하며, 같은 거래처에서도 여러 업무를 함께 처리하는 사람이다.

### 현재 겪는 문제

- 여러 업무를 동시에 처리해 업무가 헷갈리거나 누락되는 일이 생긴다.
- 다이어리와 휴대폰 캘린더에 기록하고 기존 메모를 다시 확인하지만, 가끔 업무를 빠뜨린다.
- 같은 거래처에서 서로 다른 업무가 동시에 생기면 무엇을 먼저 처리해야 하는지 판단하기 어렵다.

### 사용자 목표

거래처별 업무를 빠르게 기록하고 전체 미완료 업무를 마감시간순으로 확인하여, 마감이 가까운 업무부터 순서대로 처리한다.

## 3. MVP 핵심 기능

### 한 줄 정의

여러 거래처의 업무를 동시에 진행하는 사람이 거래처별 업무를 빠짐없이 기록하고, 마감시간이 가까운 순서대로 처리하도록 돕는 도구다.

### 3.1 업무 빠른 입력

- 첫 화면에 `거래처명`, `처리할 업무`, `처리 마감시간` 입력 칸과 `추가` 버튼을 표시한다.
- 세 항목을 모두 입력하고 `추가` 버튼을 누르면 새로운 업무가 등록된다.
- 같은 거래처에서도 서로 다른 업무를 각각 등록할 수 있다.
- 입력하지 않은 항목이 있으면 업무를 추가하지 않고 해당 입력 칸에 안내 문구를 표시한다.
- 휴대폰에서는 `달력 열기` 버튼으로 기기의 날짜·시간 선택기를 열어 마감시간을 선택할 수 있다.

### 3.2 마감시간순 업무 목록

- 등록된 미완료 업무는 거래처와 관계없이 마감시간이 가까운 순서대로 표시한다.
- 각 업무에는 거래처명, 업무 내용, 마감시간, 현재 상태와 `처리` 버튼을 표시한다.
- 같은 거래처의 업무는 거래처명이 같게 표시되지만 각각 독립된 업무로 관리한다.
- 같은 거래처의 업무에는 문의를 등록한 순서를 나타내는 접수 번호를 부여한다.
- 새 업무의 접수 번호는 같은 거래처에 등록된 마지막 번호의 다음 번호를 기본값으로 제안한다.
- 목록은 상태와 마감시간을 접수 번호보다 우선해 정렬하고, 상태와 마감시간이 같은 동일 거래처 업무는 접수 번호순으로 표시한다.

### 3.3 마감 상태 표시

- 마감까지 30분보다 많이 남은 업무는 `진행 중`으로 표시한다.
- 마감 30분 전부터 해당 업무를 최대 3회 천천히 강조한 뒤, `마감 임박` 문구와 강조 표시를 유지한다.
- 마감시간이 지난 미완료 업무는 목록 최상단에 배치하고 `기한 지남` 문구를 표시한다.
- 상태는 색상만으로 구분하지 않고 `진행 중`, `마감 임박`, `기한 지남`, `처리 완료` 문구를 함께 표시한다.
- 앱을 열어 둔 상태에서만 마감 상태가 화면에 반영되며, 앱 밖으로 별도의 알림을 보내지 않는다.

### 3.4 업무 완료 처리

- 실제 업무를 끝낸 사용자가 해당 업무의 `처리` 버튼을 누르면 상태가 `처리 완료`로 바뀐다.
- 완료된 업무는 진행 목록에서 빠지고 별도의 `처리된 업무` 영역으로 이동한다.
- 완료된 업무는 마감 임박 및 기한 지남 대상에서 제외한다.

### 3.5 자동 저장

- 입력한 업무와 처리 상태는 Supabase 업무 테이블을 기준 데이터로 자동 저장한다.
- 최초 접속 시 익명 사용자 세션을 만들고, 모든 업무는 해당 사용자에게만 보이도록 관리한다.
- 기존 브라우저 `localStorage` 업무가 있고 서버 업무가 비어 있으면 서버로 자동 이전한다.
- JSON 업무 가져오기는 Supabase 저장이 끝난 뒤에만 완료 안내를 표시한다.
- JSON 업무 가져오기 시 기존 파일의 내부 ID 대신 새 ID를 발급해 다른 브라우저 사용자의 서버 데이터와 충돌하지 않게 한다.
- Supabase 연결에 실패하면 현재 브라우저에 저장하고 기존 입력·수정·처리 기능을 계속 사용할 수 있어야 한다.
- 오프라인 중 생긴 변경은 대기 상태로 보관하고 연결이 돌아오면 서버에 먼저 반영한다.
- 한 번 서버 자료를 확인한 기기에서는 서버의 빈 목록도 유효한 최신 상태로 취급해 오래된 브라우저 자료를 다시 올리지 않는다.
- 익명 세션은 이메일 인증 링크로 영구 계정에 연결할 수 있고, 연결 뒤에도 기존 사용자 ID와 업무 소유권을 유지한다.
- 다른 기기에서는 같은 이메일의 인증 링크로 최초 한 번만 로그인해 동일한 서버 업무를 불러온다.
- 이메일 인증을 마친 세션은 해당 브라우저 또는 설치 앱에 유지되어 다음 접속부터 별도 조작 없이 자동 연결한다.
- 최초 화면은 빈 업무 목록을 먼저 표시하지 않고 서버 업무 확인 안내를 표시한 뒤 최신 자료를 보여준다.
- 서버 업무가 바뀌면 실시간 변경 전송, 20초 주기 확인, 화면 복귀 및 온라인 복귀 시 확인으로 다른 기기에 자동 반영한다.

### 3.6 최초 1회 이메일 연결

- 로그인하지 않아도 익명 사용자로 업무 화면과 모든 핵심 기능을 바로 사용할 수 있다.
- 사용자는 `PC·휴대폰 연결`에서 이메일만 입력하고, 앱은 현재 업무 유무에 맞춰 기존 업무 연결 또는 서버 업무 로그인을 자동으로 선택한다.
- 업무가 있는 최초 기기에서는 현재 익명 계정에 이메일을 연결해 기존 서버 업무의 소유권을 유지한다.
- 핸드폰 등 다른 기기에서는 같은 이메일로 받은 인증 링크를 최초 한 번 열어 동일한 계정에 연결한다.
- 비밀번호는 사용하지 않으며 인증 메일의 링크로 사용자 본인을 확인한다.
- 인증을 마친 기기에서는 매번 이메일이나 확인 링크를 요구하지 않는다. 단, 브라우저 데이터 삭제·비공개 모드·새 브라우저에서는 최초 인증이 다시 필요하다.
- 이메일이 연결된 사용자는 헤더에서 연결된 이메일, 자동 동기화 상태와 로그아웃 버튼을 확인할 수 있다.

### 3.7 설치형 바로가기

- 배포 사이트는 설치 가능한 웹 앱으로 제공하고 PC에서는 `앱 설치`, 휴대폰에서는 브라우저의 홈 화면 추가 기능을 사용할 수 있다.
- 설치 앱과 바탕화면 바로가기는 배포 주소를 열기 때문에 로컬 `index.html`이나 `assets` 폴더를 함께 둘 필요가 없다.
- 인터넷 연결이 잠시 끊겨도 기본 화면을 열 수 있으며 변경 내용은 브라우저에 보관했다가 서버 연결이 돌아오면 다시 동기화한다.

### 3.8 업무 수정, 취소 및 삭제

- 미처리 업무의 `수정` 버튼을 누르면 거래처명, 업무 내용과 마감시간을 변경할 수 있다.
- `업무 취소` 버튼을 누르면 업무를 삭제하지 않고 `취소됨` 상태로 보존한다.
- 모든 업무의 `삭제` 버튼을 누르면 거래처명과 업무명이 포함된 확인창을 표시한다.
- 삭제 확인창에서 취소하면 업무를 유지하고, 확인하면 해당 업무만 브라우저 저장소에서 영구 삭제한다.

### 3.9 업무 검색

- 전체 업무 영역 위에 거래처명 또는 업무 내용을 입력하는 검색창을 표시한다.
- 검색어를 입력하면 현재 선택한 상태 필터 안에서 거래처명과 업무 내용이 일치하는 업무만 즉시 표시한다.
- 검색은 업무 데이터와 정렬 순서를 변경하지 않는다.
- 검색 결과가 없으면 별도의 안내 문구를 표시한다.

### 3.10 스크롤 업무 카드 스택

- 업무 목록의 각 카드는 현재 정렬 순서를 유지한 채 스크롤할 때 위쪽에 겹쳐 쌓인다.
- 카드가 쌓일 때 앞쪽 카드의 크기를 조금 줄여 업무 사이의 깊이를 표현한다.
- 스크롤 효과는 업무 데이터, 상태, 정렬과 버튼 동작을 변경하지 않는다.
- 사용자가 모션 감소를 설정한 경우 겹침과 크기 애니메이션을 적용하지 않는다.

### 3.11 상태별 궤도 현황

- 상단 업무 현황의 중앙에는 전체 남은 업무 수를 표시한다.
- 중앙 주변에는 `진행 중`, `마감 임박`, `기한 지남`, `처리 완료` 건수를 타원 궤도로 표시한다.
- 상태별 건수는 업무가 추가, 수정, 취소, 삭제 또는 처리될 때 현재 데이터에 맞게 갱신한다.
- 모션 감소 설정에서는 상태 항목을 움직이지 않고 고정된 위치에 표시한다.

### 3.12 처리된 업무 기록과 후속 업무

- 진행 업무 목록 아래에 처리 완료 업무만 모은 `처리된 업무` 영역을 항상 표시한다.
- 처리된 업무에는 거래처명, 접수 번호, 처리한 업무 내용, 마감시간과 실제 처리 시각을 표시한다.
- 처리된 업무는 최근 처리한 순서로 표시한다.
- 처리된 업무의 `후속 업무 추가` 버튼을 누르면 거래처명과 다음 접수 번호를 새 업무 입력란에 불러온다.
- 후속 업무는 새로운 독립 업무로 등록하며 기존 처리 기록을 변경하지 않는다.
- 취소된 업무는 처리된 업무 영역에 포함하지 않고 진행 영역의 `취소됨` 필터에서 확인한다.

## 4. 사용자 흐름

1. 사용자는 첫 화면에서 `거래처명`, `처리할 업무`, `처리 마감시간` 입력 칸과 `추가` 버튼을 본다.
2. 세 항목을 입력하고 `추가` 버튼을 누르면 업무가 마감시간순 목록에 표시된다.
3. 같은 거래처에서 다른 업무가 생기면 거래처명과 새로운 업무 및 마감시간을 같은 방식으로 추가한다.
4. 사용자는 목록 상단의 `기한 지남` 또는 `마감 임박` 업무부터 실제로 처리한다.
5. 실제 업무를 끝낸 뒤 해당 업무의 `처리` 버튼을 누르고, 업무가 별도의 `처리된 업무` 영역으로 이동한 것을 확인한다.
6. 같은 거래처에서 후속 업무가 생기면 처리 기록의 `후속 업무 추가` 버튼으로 새 업무 입력을 시작한다.

## 5. 화면 구성

### 상단: 업무 입력 영역

- 거래처명 입력 칸
- 처리할 업무 입력 칸
- 처리 마감시간 입력 칸
- `추가` 버튼

### 하단: 전체 업무 목록

- **기한 지남:** 마감시간이 지난 미완료 업무
- **마감 임박:** 마감까지 30분 이하로 남은 미완료 업무
- **진행 중:** 마감까지 30분보다 많이 남은 미완료 업무
- **처리 완료:** 사용자가 `처리` 버튼을 누른 업무

진행 업무는 `기한 지남`을 가장 위에 표시하고, 나머지는 마감시간이 가까운 순서로 표시한다. 완료 업무는 진행 목록에 포함하지 않고 별도의 `처리된 업무` 영역에 표시한다.

### 별도 영역: 처리된 업무

- 처리 완료된 업무만 최근 처리 시각순으로 표시한다.
- 취소된 업무는 포함하지 않는다.
- 각 기록에서 같은 거래처의 후속 업무를 새 업무로 등록할 수 있다.

## 6. 데이터 항목

업무 한 건은 다음 정보를 가진다.

- 거래처명
- 처리할 업무
- 거래처별 접수 번호
- 처리 마감시간
- 상태: 진행 중, 마감 임박, 기한 지남 또는 처리 완료
- 등록 시각
- 완료 시각

## 7. 완료 기준

다음 조건을 모두 만족하면 MVP가 완료된 것으로 본다.

- 여러 거래처의 업무를 각각 등록할 수 있다.
- 같은 거래처의 업무를 여러 개 등록할 수 있다.
- 거래처명, 업무 내용 또는 마감시간이 비어 있으면 등록되지 않는다.
- 휴대폰 폭에서 `달력 열기` 버튼과 마감시간 입력란이 화면 밖으로 나가지 않는다.
- 미완료 업무가 정해진 우선순위와 마감시간순으로 표시된다.
- 같은 거래처 업무에 접수 번호가 표시되고, 상태와 마감시간이 같으면 번호순으로 표시된다.
- 접수 번호가 빠르더라도 더 급한 상태나 빠른 마감시간의 업무가 먼저 표시된다.
- 마감 30분 전 업무에 `마감 임박` 문구가 표시된다.
- 마감시간이 지난 미완료 업무에 `기한 지남` 문구가 표시된다.
- `처리` 버튼을 누른 해당 업무만 `처리 완료`로 바뀌고 목록 아래로 이동한다.
- 새로고침하거나 같은 브라우저를 다시 열어도 업무와 처리 상태가 유지된다.
- 수정한 업무 내용이 저장되고 새로고침 후에도 유지된다.
- 취소한 업무가 `취소됨` 상태로 기록된다.
- 삭제 확인창에서 취소하면 업무가 유지되고, 확인하면 선택한 업무만 삭제된다.
- 거래처명 또는 업무 내용으로 현재 목록을 검색할 수 있다.
- 업무 카드를 스크롤해도 정렬 순서와 수정·취소·삭제·처리 기능이 유지된다.
- 상단 업무 현황에서 남은 업무와 상태별 업무 건수를 함께 확인할 수 있다.
- 처리 완료 업무가 진행 목록과 분리된 영역에서 최근 처리 순서로 표시된다.
- 처리 기록에서 후속 업무 추가를 시작해도 기존 완료 기록이 유지된다.
- 최초 인증을 마친 PC와 휴대폰에서 같은 서버 업무가 자동으로 표시된다.
- 업무를 추가·수정·처리하면 열린 다른 기기에도 자동으로 반영된다.
- 설치 앱 또는 배포 주소 바로가기 하나만으로 기존 화면과 기능을 사용할 수 있다.

## 8. 이번 MVP에서 제외할 것

- 프로젝트 단계 및 프로젝트별 묶음
- 거래처 전체 완료와 프로젝트 자동 완료
- 드래그 방식 업무 순서 수동 변경
- 업무별 추가 메모
- 다이어리 내용 일괄 입력
- 휴대폰 캘린더 연결
- 앱을 닫았을 때 보내는 푸시 알림
- 결제

## 10. MVP 원칙

- 거래처는 업무를 구분하기 위한 정보로 사용한다.
- 첫 화면의 중심은 거래처별 화면이 아니라 전체 마감시간순 업무 목록으로 한다.
- 실제로 처리해야 하는 업무 한 건을 완료의 최소 단위로 삼는다.
- 2시간 안에 핵심 흐름이 작동하도록 디자인 완성도보다 입력, 정렬, 상태 표시, 완료 처리와 저장을 우선한다.
